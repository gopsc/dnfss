# Blackbird 推广文案包

> 项目定位：一套 DIY 的轻量级微服务架构（UniServe Framework），用 C++ / Python / Go / 仓颉混合实现，让个人和中小团队用极简方式拥有**自托管、可控、安全**的服务平台，免去 Kubernetes 等重型基础设施的复杂度。

### 正文

**你有没有过这种纠结？**

想做一个属于自己的小产品——一个笔记应用、一个内部工具、一个带 AI 审核的社区。可一查部署，满屏都是 Kubernetes、Service Mesh、云厂商控制台……光是看懂账单和术语，热情就凉了一半。

要是有一套东西，能像搭积木一样，让你用**一台服务器**就拥有"安全入口 + 统一鉴权 + 数据库 + AI 审核 + 业务功能"的完整能力，而且**完全自己掌控、代码开源、零云厂商绑架**——你会心动吗？

这就是 **Blackbird（UniServe Framework）** 想做的事。

---

### 它是什么？一台服务器里的"微型城市"

想象你拥有一座小城市。城市的每个功能，都由一个个**专注的小部门**负责，彼此之间通过内部街道高效协作，而整座城只有**一个安检门**对外营业：

- 🛡️ **WAF 网关**——城市的安检门。统一终止 HTTPS、挡掉恶意流量（内置 OWASP 防护规则），外面的风雨进不来。
- 🔑 **应用网关**——门内的派出所。负责统一鉴权和反向代理，确保每个请求都"验明正身"才放行。
- 🗄️ **数据库服务**——城市的档案局。所有业务的数据读写都从这里过，集中、统一、本机隔离，安全又省心。
- 🤖 **AI 内容审核**——城市的审查员。基于 RAG + 大模型自动把关内容安全，还能吸收人工反馈越用越聪明。
- ⚙️ **进程守护核心（core）**——城市的市长。负责把各个"部门"拉起来、盯好它们别"罢工"，挂了自动重启。
- 🌳 **树状笔记（dnfs）**、🤖 **AI 智能体（aibox）**、🦾 **硬件控制模块（bot4cj）**——城市里真正对外提供服务的"营业厅"和"工厂"，甚至可以控制树莓派的舵机做实体机器人。

它不是某个单一应用，而是一套**可以长出各种应用的底座**。

---

### 为什么是 Blackbird，而不是"上云"？

| 传统云原生 | Blackbird |
|---|---|
| 要学 K8s、运维集群、看云账单 | 一台机器 + 一个一键脚本搞定 |
| 数据散落在厂商手里 | 数据完全自托管，你说了算 |
| 出事要提工单等回复 | 代码开源（MIT），问题自己就能改 |
| 技术栈绑定某家云 | C++/Python/Go/仓颉多语言自由组合 |

Blackbird 不追求"承载百万 QPS 的巨型帝国"，它专注把**微服务真正有用的那部分收益**——能力拆分、统一入口、安全分层、可观测——用**最轻的量**交到你手里。

### 上手有多简单？

仓库里准备好了安装脚本：

```bash
# Debian/Ubuntu
./_setup.deb.sh
# 或 RHEL 系
./_setup.rhel.sh
```

然后 `systemctl start Nidus`，核心会按配置自动拉起所有服务。从外部访问，你只需要记住一个地址——`https://你的域名`，安全、鉴权、转发全在背后默默处理好。

### 它适合谁？

- 🧑‍💻 **独立开发者 / 个人站长**：想拥有自己的服务平台，又不想被运维压垮。
- 🏢 **中小团队**：需要一个可控、低成本的内部中台，不依赖外部 SaaS。
- 🔐 **注重数据主权的人**：数据必须握在自己手里。
- 🤖 **AI / 硬件爱好者**：想玩转 AI 智能体、嵌入式舵机，又想要一个稳的底座。
