## 🔴 P0 — 严重问题

### P0-1: 零认证对外开放完整 CRUD（依赖 127.0.0.1 网络隔离）
- **位置**: `dbv2.py` RpcServer
- **问题**:
  - 完全没有认证机制
  - 任何能访问 8005 端口的本地进程/用户都可执行任意 select/insert/update/delete
  - 可读取 Users 表密码哈希、Logs 表所有日志
  - SELECT 无 limit 上限，可被拖库
  - 无表级/操作级权限控制
- **当前缓解**: 默认监听 `127.0.0.1`，Docker 也绑定到 127.0.0.1
- **修复建议**:
  1. 添加 API Token 认证（预共享密钥，所有调用需携带 `_auth` 字段）
  2. SELECT 强制添加 LIMIT 上限（默认 1000 条），防止拖库
  3. 添加操作权限：日志写入只允许 insert，禁止 delete/truncate
  4. 拒绝无条件 UPDATE/DELETE（必须带 where 条件）
  5. DDL 操作仅限本地运维工具，RPC 接口完全禁用

## ✅ 已有安全机制

1. ✅ **SQLAlchemy Core 参数化查询**：核心 CRUD 路径使用表反射 + 参数化，零 SQL 注入风险
2. ✅ **仅监听 127.0.0.1**：不对外暴露
3. ✅ **集中式日志 fail-safe**：db 不可用时静默丢弃，不阻塞业务
4. ✅ **自动提交/回滚**：异常时自动回滚事务
5. ✅ **日期/时间适配**：ISO 8601 处理，`"$now"` 哨兵
6. ✅ **日志自动清理**：后台线程每小时清理，防止磁盘占满
7. ✅ **log_client 健壮性**：异步队列、后台线程、fail-safe、队列上限（从各服务副本）
