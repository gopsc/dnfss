## 🔴 P0 — 严重问题

### P0-1: RSA 私钥持久化问题 — ✅ 已修复（设计接受）

- **位置**: `main.cpp` L967 `_KEYGEN = std::make_unique<MyRSA::Generator>();`
- **当前状态**: ✅ 已修复（按设计接受）
- **修复说明**:
  - 密钥由 `MyRSA::Generator` 在内存中运行时生成，**未硬编码在源码中**
  - 每个进程实例独立生成密钥对，满足"每个部署独立密钥"要求
  - **设计决策**: 进程重启后 RSA 密钥对重新生成，旧 Token 因 RSA 验签失败而自然失效，这是一种有效的隐式密钥轮换机制
  - 配合 Token 版本号机制（`_USER_VER_MAP`），重启等同于全量 Token 吊销，安全风险可控
- **备注**: 如需持久化密钥（避免重启后用户需重新登录），可后续从文件加载；当前设计在安全性上更优（重启即吊销）。

### P0-2（新增）: 错误页面泄露版本号/堆栈信息 — ✅ 已修复

- **原编号**: P2-1（初版），升级确认后确认核心问题已解决
- **位置**: `main.cpp` L1167-1213、`ExpBase.hpp` L173-197
- **当前状态**: ✅ 已修复
- **修复说明**:
  - `wrapperHttp` 中 `std::exception` 捕获分支已不再返回 C++ 类型名和 `what()` 详情，统一返回 `"Internal Server Error"`
  - `ExceptionBase::build_message()` 中源码文件路径、行号、函数名、嵌套异常等位置信息已全部注释，`what()` 仅返回错误码和业务消息
  - 完整错误详情仍通过 `std::cerr` 输出到服务端日志，并写入 db `Logs` 表供排障
  - 服务端日志记录完整异常链，不影响排障能力

### P0-3（新增，原初版P2-1延伸）: HttpException 业务消息返回 — ✅ 已修复

- **位置**: `main.cpp` L1179-1181, L1318, L1381, L1882, L2205
- **当前状态**: ✅ 已修复（2026-08-07）
- **修复说明**:
  - `HttpException` 被捕获后，`e.what()` 仍写入客户端 JSON 响应的 `message` 字段，但已确保不暴露敏感信息
  - **已解决**: 不再返回源码路径、行号、C++ 类型签名等敏感信息（P0-2已修复）
  - **已修复**: 4处暴露内部步骤的错误消息已全部替换为用户友好文案：
    - `"Login (Query Step) Failed"` → `"Login failed, please try again later"`
    - `"Login (Update Step) Failed"` → `"Login failed, please try again later"`
    - `"Registe Failed"` (拼写错误+400) → `"Registration failed, please try again later"` (修正为500)
    - `"Reset Failed"` → `"Password reset failed, please try again later"`
  - 详细错误信息仍记录在服务端日志（stderr + db Logs表），不影响排障
- **修复验证**: 所有500错误消息均为用户友好的通用文案，不再暴露内部实现步骤

## 架构安全评估

### 安全分层（纵深防御）

```
互联网
  ↓
waf:443 [TLS终止 + coraza规则匹配 + 速率限制]
  ↓
gateway:8443 [鉴权 + Token + 限流 + 代理白名单 + 路径校验]
  ↓
  ├─ static:9200 [前端托管 + 路径遍历防护]
  ├─ dnfs:8006 [树状笔记 + AI内容审核]
  └─ （db/ai_review/captcha/smtp/confs 不对外暴露）
```

### 安全优势

1. **多层防护**: WAF边缘防护 + gateway应用层鉴权 + 服务最小暴露
2. **密码安全**: PBKDF2慢哈希 + 唯一盐值 + 恒定时间比较
3. **Token安全**: RSA签名 + 完整吊销机制 + 生命周期控制
4. **防枚举**: 登录/重置均有时序拉平和统一响应
5. **fail-closed**: 验证码/邮件服务不可用时拒绝请求，而非放行
6. **内存安全**: C++20 智能指针 + RAII，无手动内存管理
7. **异步安全**: 日志fail-safe设计，后端故障不影响主业务
8. **重启即吊销**: 密钥内存生成，重启后所有旧Token失效

### 剩余风险

1. **CSRF**: POST接口缺少CSRF Token，依赖SameSite=Lax防护
2. **CORS**: 白名单配置未生效，跨域策略依赖libhttp默认行为
3. **账户锁定**: 仅IP级限流，可被代理池绕过进行定向账户爆破
