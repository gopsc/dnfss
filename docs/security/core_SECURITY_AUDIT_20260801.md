## 🔴 P0 — 严重问题

### P0-1: PMC HTTP 管理接口无认证，可执行任意系统命令
- **位置**: `src/main/HttpTask.cpp` L58、L130-142
- **当前状态**: ⚠️ 部分修复
  - ✅ 管理接口已绑定 `127.0.0.1`（`HttpTask.cpp` L58），仅本地可访问
  - ❌ MQ 通道的 `kill`/`exec` 操作**仍在活跃执行**（`main.cpp` L283-296），L282 注释标注"在身份验证之前禁止操作"但代码未实际禁用
  - ❌ **HTTP 端点 `/exec`、`/kill`、`/list` 仍无任何认证**（`HttpTask.cpp` L130-142），本地任意进程可调用
  - ❌ 无操作审计日志
- **修复建议**:
  1. ~~确保管理接口仅监听 127.0.0.1~~ ✅ 已实现
  2. 添加强认证（预共享 Token 或 Basic Auth over localhost）
  3. 危险命令（exec、kill）要求二次确认
  4. 记录所有管理操作审计日志

### P0-2: init.txt 配置文件无完整性校验，可注入恶意命令
- **位置**: `src/main/pmc_mtd.cpp` L90-118 `parse_self_init_list()`
- **当前状态**: ❌ 未修复
  - 无数字签名/校验和验证
  - 无文件大小限制检查
  - 支持 `#` 注释行跳过（基础防护），但命令行内容无任何校验
  - 逐行读取后直接 `ppool.crtp(row)` 创建进程
- **修复建议**:
  1. init.txt 添加数字签名/校验和验证
  2. 运行时监控 init.txt 修改，变更需管理员确认
  3. 文件权限设为 0600，仅 root/运行用户可写

## ✅ 已有安全机制

1. ✅ **进程生命周期管理**: 自动重启异常退出的子进程，保障服务可用性
2. ✅ **线程池模型**: 固定线程数，防止无限线程创建
3. ✅ **日志集中管理**: 统一日志格式和输出
4. ✅ **C++ RAII 内存管理**: 使用智能指针减少内存泄漏风险
5. ✅ **依赖审计**: 使用经过审计的 libth 线程库、libhttp HTTP 库、libcrypt 加密库
6. ✅ **管理接口本地绑定**: HTTP 管理接口仅监听 `127.0.0.1`（`HttpTask.cpp` L58）
7. ❌ **MQ 通道危险操作未禁用**: `kill`/`exec` 通过消息队列的路径**仍在活跃执行**（`main.cpp` L283-296），L282 注释标注"在身份验证之前禁止操作"但代码未实际注释禁用
