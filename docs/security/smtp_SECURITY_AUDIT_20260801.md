## 🔴 P0 — 严重问题

### P0-1: 旧版 smtp.py 存在大量致命漏洞（需立即下线） ⚠️ 部分修复
- **位置**: `smtp.py`、`_run.sh`
- **问题**: 旧版 smtp.py 缺乏关键防护：
  1. 无发送速率限制（可被用于邮件炸弹）
  2. 无同邮箱 60 秒发送冷却
  3. 无验证码过期清理机制
  4. 无连续失败锁定机制
  5. 存在 `NameError` 风险：`server.quit()` 在 finally 块中，若 SMTP 连接失败导致 `server` 未赋值则崩溃
- **已确认**: `_run.sh` L6 使用 `exec python3 smtp_v2.py`，生产环境已切换至新版
- **仍缺失**: 旧版 `smtp.py` 仍存在于代码库中，可被误启动
- **修复建议**:
  1. 删除或重命名旧版 `smtp.py`（如 `smtp.py.deprecated`）防止误用
  2. 在代码注释中明确标记废弃

### P0-2: 依赖 pymsg 无认证（缓解：绑定 127.0.0.1）
- **说明**: 与其他 pymsg 服务相同，当前依赖网络层隔离

|---|------|------|

| P1-2 | 全局发送熔断配置需确认生效（`SMTP_HOURLY_LIMIT`） | smtp_v2 已有但需验证环境变量正确加载 |

## ✅ 已有安全机制（smtp_v2.py）

1. ✅ **同邮箱 60 秒发送冷却**: 冷却期拒绝并返回 `retry_after`
2. ✅ **邮箱级限流**（gateway 层双窗口：3次/小时 + 10次/天）
3. ✅ **验证码一次性消费**: 校验通过立即删除，防重放
4. ✅ **连续失败 5 次自动作废**: 防暴力破解验证码
5. ✅ **10 分钟有效期**: 惰性过期清理
6. ✅ **发送失败不计入冷却**: 防止网络错误误限制
7. ✅ **全局熔断（可选）**: `SMTP_HOURLY_LIMIT` 默认 100 封/小时
8. ✅ **fail-closed**: SMTP 异常时验证码校验失败
