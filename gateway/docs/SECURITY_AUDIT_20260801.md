## 🔴 P0 — 严重问题

### P0-1: RSA 私钥存储在仓库中/硬编码
- **位置**: Token 签名相关代码
- **问题**: RSA 私钥若硬编码在代码中或随仓库分发：
  - 所有部署使用同一密钥对，私钥泄露即全局沦陷
  - 任何有代码访问权限的人都可伪造 Token
- **修复建议**:
  1. 私钥从文件路径加载（启动参数或环境变量），不硬编码
  2. 每个部署实例生成独立密钥对
  3. 私钥文件权限 0600，仅服务运行用户可读
  4. 公钥分发机制：dnfs、aibox 等需要验签的服务可访问公钥

## ✅ 已有安全机制

1. ✅ **PBKDF2 密码哈希**: 慢哈希算法防彩虹表，使用唯一盐值
   ```cpp
   bool auth_ok = PBKDF2Hasher::verify_password(password, stored_hash);
   ```
2. ✅ **RSA Token 签名**: Token 使用 RSA 私钥签名，防伪造
3. ✅ **反向代理架构**: 统一入口，隐藏后端服务拓扑
4. ✅ **速率限制**: 邮件轰炸多层防护（gateway+smtp 双窗口限流、60秒冷却、失败锁定）
5. ✅ **防用户名枚举**: 登录失败返回统一消息（需确认实现）
6. ✅ **WAF 前置防护**: Go WAF 处理 SQLi/XSS/CC/协议解析
7. ✅ **C++ 高性能实现**: 避免 Python GIL 瓶颈，抗并发能力强
8. ✅ **依赖审计**: 使用项目自带的 libcrypt 加密库（PBKDF2、RSA）
